**Short keyboard checks and optional English experiments**

These native windows collect local physical events while the global router is suspended through the existing probe-focus callback. They do not request Accessibility, synthesize system keys, install dictionary changes, or run the advanced matrix scan.

The confidence label distinguishes the measured bundled ISO model (MacBookPro18,1; 998 of 999 observations explained), the unmeasured ANSI derivation, saved user scan observations, and an unchecked/custom profile. Selecting any model does not test the connected keyboard. An OS keyboard type and computer model do not identify an external keyboard. Saved scans remain explicitly unconfirmed against the current keyboard unless their association is supplied deliberately.

The short check offers sat, hat and tan, a requested practice word, or the planner's available alternatives for A, H, J and K. It records the largest simultaneously held target subset and any extra key, then completes an observation only after all registered keys are released. The text describes incomplete evidence rather than diagnosing matrix blocking. Retry preserves earlier observations; skips create no observations. Focus loss, mouse interaction and shortcut modifiers discard a pending attempt. Shift can be pressed after the target keys while they remain held. Tab navigates controls; Focus chord input returns to capture.

The opt-in ergonomic sandbox compares existing routes with Quote+U+S for ‘use’ and Quote+Y+O for ‘you’. It copies English data locally and leaves the original English/shared/C++ dictionaries intact. C++ Quote+U+S continues to produce ‘using’. A proposal is excluded if its English chord is assigned, absent, over the key limit, or excluded by keyboard limits. Both proposed and current routes must replay exact output and spacing in fresh text and after ‘sat’; an unavailable baseline cannot produce an unpaired comparison.

Each compatible word has two repetitions in each context. The first repetition uses current then proposed; the second reverses the order. Timing starts on the first physical press and includes incorrect attempts/retries until successful local output. Corrections and self-rated comfort (1–5) are reported separately. Repeats, unmatched releases, interrupted attempts, paste and ordinary control navigation cannot complete a trial. Inline comfort selection avoids a modal window and preserves the focus lease. Cancel retains already rated measurements for export; New / Reset creates a fresh local session.

Only aggregate results are saved on explicit Save or copied on explicit Copy: keyboard/profile/computer identity, target chord evidence, or fixed-task route, context, repetition, duration, correction count and comfort rating. Neither window saves a raw event trace or arbitrary typed text. The app callbacks write quick-chord-check.txt and ergonomic-trial.txt in its existing local data directory. Those files are replaced only by explicit saving of another report.

The automated checks use simulated deterministic core events to validate state transitions and output. They are not hardware measurements. As of this implementation, no human speed, comfort, retention, finger-load or physical reliability measurements have been collected. The interface consequently infers no preferred route and makes no frequency-weighted coverage or globally optimal layout claim. A small paired session still has practice, order and hand-preference effects; compare matched contexts and repetitions and repeat on a later day before adopting a route.
